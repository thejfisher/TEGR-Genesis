# TEGR Genesis v0.1a — engine fix notes (2026-10-18)

Sandbox copy of `TEGR-Genesis` commit `e8aff55`. Local git only, nothing pushed.

## The bug
A moving **Active Body** (feeds the field while it moves) pushed itself forward.
- A lone star sped up by +0.7% / +7% / up to +155% per time unit on coarse / base / fine grids.
- In a heavy orbit, the star was flung out to 5× its starting radius.

## Cause 1: force read one tick too late (main bug)
- Each tick the engine stepped the field to `phi(n+1)`, then read the force from `phi(n+1)` at the star's old position `x(n)`.
- The star's own well moves with it. One tick ahead, the star sat `v·dt` **behind** its own well centre.
- The slope there points forward, so the star pushed itself ahead.
- That predicts a push that grows like `dt / dx³`, which matches the grid check: it halved with dt and grew about 8–10× per halving of dx.

**Fix:** the force is now read from `phi(n)`, the field at the star's own time step.
- Setting: `time_centred_force = True` (on by default).
- The MS38 rule only. Legacy 2600 is unchanged.

## Cause 2: sharp one-cell cloud (smaller leftover)
- After fix 1, fast stars (0.4c) still sped up a little, and more on finer grids: +0.3 / +1.6 / +10% per time unit on coarse / base / fine.
- Half dt gave the same number as base, so this part is a **grid-size** effect, not a time-step effect.
- It comes from the 2×2×2 cell (CIC) cloud shaking as the star crosses cell faces.

**Fix:** a smoother cloud for Active Bodies. Setting `body_kernel`:

| Option | What it is | 0.4c lone star (coarse / base / fine) |
|---|---|---|
| `cic` | old 2×2×2 cloud | +0.34 / +1.58 / +10.1 %/t |
| `tsc` **(default)** | 3×3×3 cloud | +0.03 / +0.15 / +0.59 %/t |
| `gauss` | Gaussian, fixed size `body_width` (default 2.8125) | +0.12 / −0.006 / −0.006 %/t |

- Tracers, wells and anchors always use CIC, so their results are unchanged.
- The default is TSC (your choice). Note: TSC still drifts a little at 0.4c on the fine grid (+0.6%/t).
- Gaussian is the only option that gives the same answer on base, fine and half-dt.
- In the app window: the new **Body cloud** and **Body width** rows.

- The old `results/spinning_disk.*` (buggy engine) is kept for comparison.
- Disk spin change after 60 time units. Only stars still in the box at the end are counted.

| Run | OLD engine | TSC | Gaussian (trust this one) |
|---|---|---|---|
| alpha 0, P (all prograde) | +9.1%, 53% left | −46.7%, 67% left | −45.3%, 72% left |
| alpha 0, C (half each way) | +2.8% / −15.0%, 68% | −39.2% / −25.3%, 90% | −23.2% / −21.0%, 95% |
| alpha 0, T (tracers, no wake) | 0.0% | 0.0% | 0.0% |
| alpha 0.1, P | −97.8%, 14% left | −95.0%, 35% left | −71.7%, 59% left |
| alpha 0.1, C | −93% / −102%, 17% | −73% / −77%, 50% | −49% / −47%, 72% |
| alpha 0.1, T | 0.0% | 0.0% | 0.0% |

What it shows (honest reading):
- The disk no longer **gains** spin. The old +9% was the self-push bug.
- Active disks still lose a lot of spin and spread out. The tracer control (T) stays at 0%, so the field motion matters.
- TSC and Gaussian agree for alpha 0 P (−47% vs −45%). They disagree elsewhere, most at alpha 0.1 where stars are fastest. That is TSC's grid error at high speed.
- **Not yet proven to be "wake drag".** This disk is cold and heavy (disk 140 vs centre 60). In plain Newton gravity such a disk breaks into clumps and throws stars out, and the stars that leave carry spin with them. That alone could explain much of the loss.
- The outer pull drops after release (0.83–0.90 for P at alpha 0). That fits mass moving outward and leaving the box, not extra "dark" pull.

## Newtonian control test (2026-10-18)
Ran the exact same disk with instant (Newton, infinite wave speed) gravity and the same star size (`sigma = 2.8125`).
- Script: `experiments/spinning_disk/newton_control.py`
- Outputs: `results/newton_control.json` and `results/newton_control.png`

| Run | Instant Newton (c = ∞) | Genesis Wave (c = 65) | Difference (Wave wake?) |
|---|---|---|---|
| **P** (all stars prograde) | **−38.0%** spin, 71% left | **−45.3%** spin, 72% left | **−7.3%** extra spin loss |
| **C** (stars orbiting with) | **−21.3%** spin, 95% left | **−23.2%** spin, 95% left | **−1.9%** |
| **C** (stars orbiting against) | **−19.4%** spin, 95% left | **−21.0%** spin, 95% left | **−1.6%** |
| **T** (tracers, no self-gravity) | **+0.00%** spin, 100% left | **−0.00%** spin, 100% left | **0.00%** |

### Key takeaways (plain English):
1. **Most of the spin loss is ordinary Newtonian disk dynamics.**
   - In pure Newtonian gravity, the cold, heavy disk also loses **38%** of its spin (in Case P) and throws out 29% of its stars.
   - In Case C (counter-rotating, which stops bar clumping), both Newton and Genesis lose **~20–23%** of spin and keep 95% of stars.
2. **The real wave wake effect is modest (~2% to 7%).**
   - The extra spin drag from finite wave speed is only **−7.3%** in Case P and **−1.6% to −1.9%** in Case C.
   - It is not a massive ~50% drag; most of the change is stars scattering gravitationally off each other.
